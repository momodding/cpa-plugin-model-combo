# Quota tracking dashboard

## Context

Add a Quota tracking tab beside Usage tracking to configure quota polling and monitor its results. Implement quota-aware headroom routing because the current router does not consume quota, and use a configured default of 50% for unknown current quota rather than guessing or reusing last-known values. The existing `.omp/plans/TITLEHEADROOM_QUOTA_ROUTING_PLAN.md` is historical implementation guidance, not evidence of shipped functionality; this plan explicitly overrides its unknown-policy and stale-cache rules.

## Approach

1. **Isolate work and preserve existing changes.** Start a dedicated feature worktree and branch from the current HEAD, not marketplace/main. The source working tree has user-modified `AGENTS.md` and `management.go`; do not stash, revert, stage, or commit them. Transfer the existing `management.go` changes into the feature worktree without changing the source tree, and build on them. Do not transfer or commit the unrelated `AGENTS.md` modification. Persist this approved plan in `plans/quota-tracking-dashboard.md` in the feature worktree. Follow the project-rule exception selected by the user: a single feature commit only after relevant local unit tests pass; push and open a PR, with GitHub CI used for end-to-end verification. Never merge automatically.

2. **Record decisions.** Add the next unused zero-padded ADR and BDR under `docs/adr/` and `docs/bdr/` in the feature worktree (currently 0007 in this working tree; do not assume the historical plan's 0008 exists). Record that headroom is opt-in per route, unknown quota uses the configured percentage, expired or failed polls never supply stale scores, and diagnostics contain no credentials or raw upstream responses. Preserve ADR/BDR 0006's account restriction, privacy and usage-attribution guarantees.

3. **Restore and extend management dispatch.** The modified `management.go` currently references undefined `quotaDiagnostics(plugin)` and has an incomplete accounts case; this is a pre-existing compile blocker. Restore the accounts GET handler using `plugin.accountCatalog(host)` and its existing catalog-unavailable response; preserve existing endpoint behavior. Implement the already registered `GET /v0/management/plugins/model-combo/quota-status` using the actual quota manager below, with method validation and safe diagnostics. Do not introduce a competing `/quota` endpoint.

4. **Implement the historical headroom design with these explicit overrides.** Use `.omp/plans/TITLEHEADROOM_QUOTA_ROUTING_PLAN.md` sections Platform facts, Architecture, Config, Normalized quota model, Provider adapters, QuotaPollingManager, Routing and Tests as the detailed specification for provider acquisition, loopback-only management URL, fixed upstream destinations, timeouts, bounded concurrency, session affinity, restricted-account eligibility, streaming, fallback and tests. It is available in the source worktree; if it is untracked, copy its content into the feature worktree as a temporary implementation reference without committing it. Its statements about current files or decision-record numbering are not authoritative. Specific changes:
   - Add `headroom` route strategy and top-level `quota_polling` settings with the historical plan's numeric polling defaults and validation. Add `default_unknown_quota_percent` to `quota_polling`: a finite number from 0 through 100, default 50 when omitted, interpreted as the remaining percentage for each unknown account/model candidate. Persist it with the other plugin configuration fields and present it as a numeric form field. This is a score, not a claim of provider quota or an amount of tokens.
   - Do not add historical `unknown_quota` values `priority`, `exclude`, or `last`: all unknown candidates receive the configured score divided by 100, and sort together with known candidates by descending score. Ties use target order then eligible account order. Preserve the historical explicit handling for observed partial, unlimited and exhausted snapshots, including dropping observed exhausted candidates; a default of 0 remains an unknown score, not an observed exhausted state.
   - A missing, unsupported, failed, unparsable, or older-than-`ttl_seconds` current poll is unknown immediately. Do not use earlier successful windows for ranking or display as current; the manager may retain backoff metadata but not use its prior snapshot as the effective score. This replaces the historical `max_stale_seconds` last-known scoring behavior. Identify unknown reasons in diagnostics. A failure after a successful poll immediately switches to the default.
   - Modify only headroom routes to pin and rank eligible account/model pairs; other strategies retain existing behavior. `routeAccounts` currently returns no account catalog for unrestricted routes: for headroom specifically enumerate compatible enabled accounts through `accountCatalog`, while restricted routes continue to honor `allowed_accounts` order and fail closed on catalog failure. Reuse existing fallback, cooldown, request cancellation and stream safety logic. Preserve the existing attempt limit semantics; no request may escape a restriction or retry after a stream payload.
   - Implement polling through the historical plan's fixed provider endpoints and management proxy, not inferred usage or fabricated quota. If an SDK field or provider prerequisite is unavailable, report that provider as unknown with a sanitized reason. Missing `MODEL_COMBO_MANAGEMENT_KEY` likewise yields unknown; do not expose or persist it. Diagnostics expose safe account labels, provider, applicable windows, source, freshness, reason and effective score, plus polling and last-selection status; never expose tokens, headers or raw errors.

5. **Build the sibling dashboard.** Add the `quota-tab` button directly after `usage-tab` and an accessible `quota-panel` in `dashboard.html`, following the existing embedded include pattern and visual language. Extend `activateTab` and `handleTabKey` in `dashboard/usage/tab.js` and click dispatch in `dashboard/app.js` to handle all three tabs, maintain `aria-selected`, focus and panel visibility, and stop polling when a panel is inactive. Add a quota panel with the historical `quota_polling` controls and a labeled `Default unknown quota (%)` input, 0–100, initially 50. Reuse the existing configuration load, validation and save flow so saving from either tab preserves routes and polling settings; show validation/save failures without losing edits. Display account/provider, current windows and reset time, current status, effective percentage, observed vs configured-default source, freshness and sanitized error reason. Refresh the diagnostic endpoint on opening and periodically only while the panel is visible; show loading, unavailable, empty and stale/unknown states without representing them as live data. Expose the `headroom` route strategy in the existing route editor.
